# Editing this site

This site is plain HTML/CSS/JS — no build step, no server-side CMS.
You can edit it directly on GitHub, locally, or through the built-in
Admin Studio. Vercel redeploys automatically on every push.

## The Admin Studio (`/admin`)

Open `admin/index.html` (locally, or on your deployed site at
`yoursite.com/admin/`). It's a password-gated, in-browser content
editor — no server, no database.

**Password:** `kolouch2026` — change this by editing the
`GATE_PASSWORD` constant near the top of `admin/studio.js`.

**Important — read this once:** the password gate is a light
deterrent, not real security. The password lives in plain text in
`studio.js`, visible to anyone who views the page source. It stops
casual visitors from poking around; it does not stop anyone who
actually wants in. If you want the admin folder genuinely private,
either don't deploy it (delete `/admin` before pushing to your live
site and only use it locally), or password-protect the whole path at
the hosting level (Vercel supports this on paid plans).

### What it does

- **Publications** — see everything in your current draft, edit or
  delete any entry.
- **New / Edit** — write a full article in Markdown, *or* attach a
  PDF and/or Word document as downloadable source material (with a
  short intro text). Upload a cover image. Add tags. Set category,
  date, and an optional external link (e.g. if the piece is
  published on LinkedIn instead of hosted here).
- **Categories** — add, rename, or delete the categories that power
  the filter buttons on Research/Publications.
- **Media Library** — upload images once, reuse them anywhere.
- **Export** — bundles your draft into a `.zip`: updated
  `content/articles.json`, new Markdown files, uploaded images, and
  PDF/Word attachments, all correctly named and placed, plus a
  `README-CHANGES.txt` with exact steps.

### The publish workflow

Nothing in the Studio is live until you export and commit it:

1. Make your changes in the Studio (they autosave to your browser's
   local storage as you go — safe to close the tab and come back).
2. Go to **Export** → **Download Export Bundle**.
3. Unzip it, drag the contents into your GitHub repo (overwriting
   `content/articles.json` and `js/articles-data.js`, adding new
   files under `content/articles/`, `content/attachments/`, and
   `images/uploads/`).
4. Commit. Vercel redeploys in under a minute.

This "prepare → export → commit" model exists because this is a
static site with no backend to save files to permanently. It's the
honest tradeoff for a site with zero hosting cost and no server to
maintain.

## Editing content without the Studio

You can also just edit files directly — useful for quick text fixes.

### Page text

Open any `.html` file on GitHub, click the pencil icon, edit, commit.

### Articles

- `content/articles.json` — one entry per article (title, category,
  excerpt, tags, dates, links).
- `content/articles/*.md` — full article bodies in plain Markdown.
- `content/attachments/*` — PDF/Word files linked from an article.
- A single template, `article.html`, renders whichever article
  matches its `?slug=` — no per-article HTML files to maintain.

See the example entries already in `content/articles.json` for the
exact shape — copy one and adjust it.

## Local preview

Articles load via `fetch()`, which browsers block for files opened
directly from disk in most cases — except this site also ships an
offline fallback bundle (`js/articles-data.js`, regenerated by the
Studio's Export, or manually via the note in that file) so double-
clicking `index.html` still works without a server. If you edit
`content/articles.json` directly (not through the Studio) and want
to preview those exact changes locally, run a quick local server so
the fetch works against the live file:

```
python3 -m http.server 8000
# or
npx vercel dev
```

## Dark / Light mode

Toggled via the moon/sun icon in the nav (saved per-browser in
`localStorage`). The navy nav, hero, and footer stay navy in both
modes by design — only the white/off-white content sections switch.

## Newsletter signup

The form currently simulates a successful signup client-side — there's
no backend collecting emails yet, because this site has no server.
The fastest real fix (no code, ~2 minutes): sign up for a free
[Formspree](https://formspree.io) account, get your form endpoint,
and:

1. Add `action="https://formspree.io/f/YOUR_ID" method="POST"` to
   both `<form class="newsletter-form">` elements (in `index.html`
   and `contact.html`).
2. Remove the `e.preventDefault()` simulation in `initNewsletterForm()`
   in `js/main.js` (or leave it — Formspree also works via a normal
   form POST with no JS at all).

Any similar service (ConvertKit, Mailchimp embed, Buttondown) works
the same way.

## The `/admin` folder and deployment

If you'd rather not ship the admin editor to your public production
site at all, delete the `/admin` folder before your final deploy and
just use it locally (`python3 -m http.server` from the project root,
then open `localhost:8000/admin/`) whenever you want to prepare an
update.
